# Support v1 — admin implementation contract, 2026-10-04

Status: proposed DTO before implementation; transfer acknowledged in ownership revision 4. This document does not claim implemented endpoints. Admin owns club/support_admin.py, additive audit storage, targeted tests, one __init__.py registration hunk, admin.html consumer and admin-only JS/CSS. UI owns help.html consumer. Existing help GET/POST and original tickets remain intact. No third-party messaging.

GET /api/support/tickets: session required. Editor/admin returns tickets for handling; learner returns only own tickets. No email or entitlement fields. Version 1 envelope: {version:1,tickets:[{id,lesson_id,body,created_at,status,revision,response,handled_at}]}. status is open or handled; response/handled_at null until handled. Original body and lesson_id never editable through this API. Admin may receive learner display name and lesson title, but no other account data. Learner must never receive handler user ID or other learners' records. GET /api/support/tickets/<id> returns same DTO, 404 for another learner's ticket.

POST /api/support/tickets/<id>/handle: editor/admin only; same-origin session and existing CSRF checks mandatory. Body {revision:0,response:"Plain text response, 1–4000 characters"}. Atomic revision check; append response, handler and timestamp to audit table, update help_requests.status to handled in same transaction. Exact repeated current response may return same DTO without duplicate audit; stale differing revision returns 409 without overwrite. 400 invalid payload, 403 wrong role/CSRF, 404 missing ticket. Return {version:1,ticket:...}. Keep handler ID internal. No promise of notification delivery or response time. Additive initialized storage must back up populated DB before migration.

Admin task: expand question → enter response → mark handled → explicit saved/error state. Preserve text on failed/conflicting save; offer reload without silent loss. Learner task: existing help page loads own status/response through GET, renders plain escaped text; no raw HTML. If API fails, keep original question and show retry. Handled means a response was recorded, not that learner confirmed resolution.

Independent acceptance: real learner post → editor reply → learner reload; other learner 404/list isolation, learner action 403, missing CSRF 403, stale simultaneous handling 409, replay no duplicate row, restart persistence; original body/context retained. Admin and UI implementations still pending; P2 remains open.
