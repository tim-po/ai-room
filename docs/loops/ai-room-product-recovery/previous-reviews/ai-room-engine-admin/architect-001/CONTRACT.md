## Implemented learner contract

- GET /api/skills/graph returns recursive nodes, root, typed contains/prerequisite/related edges, mappings, release. Whole graph remains browsable; membership is separate from prerequisites. Graph edits validate duplicate/dangling/cycle and immutable historical identities.
- GET /api/skills/nodes/<node_id> returns content, assessment metadata, pending/recovery metadata and access requirements, never keys. GET /api/skills/me returns interests/explorations, coverage, understanding evidence, application evidence and pending attempts. Unknown is unassessed; activity/completion is not understanding/application. Root coverage is whole tree; foundation_coverage excludes major branches.
- PUT /api/skills/interests {node_ids:[...]} replaces optional interests; POST /api/skills/explore {node_id} records exploration independently. Legacy onboarding GET/POST /preferences and POST /preferences/skip persist goal/experience/time; UI must not turn those into exclusive branch selection. Replacing interests never deletes exploration/evidence.
- POST /api/skills/challenges {assessment_id,request_id}; GET /api/skills/challenges/<id>; POST /api/skills/challenges/<id>/submit {answers:{item_id:choice_id}}. Request IDs 8–128 chars and unique per learner; same key/form replays, changed form conflicts. Resume and submit owner-only. Keys/rationales server-side until submission; immutable result replay. Shared lineage/canonical item exposure across historical releases makes retakes practice-only; overlapping pending attempt returns 409 with pending_attempt recovery DTO. Credits unique per learner/objective/revision/kind; never write video or completion state.
- POST /api/skills/diagnostics {request_id,interests:[...]}; GET list and /<id>; POST /<id>/advance {revision,attempt_id} or {revision,skip:true}. Scope pinned to original release; foundations then multiple interests, cap eight observations, restart/resume supported. DTO includes state/next/observations/recommendations/verified/unknown. Current dynamic state completed means no next form; it is NOT mastery or the stricter analytics completion definition. A1 must fix protected-source filtering and inaccessible next-form planning without dropping history.
- GET /api/skills/practical-tasks[?node_id=...] and /<id>; POST /api/skills/practical-submissions {task_id,request_id}; GET list and /<id>; PUT /<id> {revision,body,status:draft|submitted}. Submitted work freezes; revisions become new submissions after review. Human review uses per-criterion met/not_met/uncertain; uncertain never creates application credit. A1 must apply current bound-content access consistently across task/submission APIs.
- Baseline /api/lessons/<id> plus /completion, /practice, /video retain server persistence and stable IDs. Existing CSRF header X-CSRF-Token applies to every mutation. Same-origin session auth; ownership failures conceal others' records; access revocation preserves earned summaries, never protected body/source.

## Implemented editorial contract

GET/POST /api/skills/graph-proposals, GET/PUT /<id>, POST /<id>/<activate|reject|rollback>, GET /api/skills/graph-history. Proposal revisions use compare-and-swap; activation requires current base, explicit review, availability impact and separate taxonomy decision. Compatible edition bindings preserve original form/task IDs; rollback keeps attempts/evidence and cannot revive withdrawn forms. No automatic semantic equivalence from IDs or text similarity.

GET /api/skills/forms exposes staff lifecycle/impact inventory; POST /api/skills/forms/<id>/withdraw records reason and optional replacement. Withdrawal preserves all prior data and blocks new certification; completing retained withdrawn work cannot issue new credit. Historical replacements are resolved without losing access-recovery routes.

POST /api/skills/practical-tasks is staff reviewed-rubric publication. GET /api/skills/practical-review lists submitted others' work. POST /api/skills/practical-submissions/<id>/review {revision,ratings,feedback} records immutable decision; self-review forbidden; incompatible replay conflicts.

GET /api/teaching/capabilities exposes formats/limits/provider status names, never credentials. POST /api/teaching/uploads is multipart file with Idempotency-Key (8–100 alphanumeric/_/-); same owner/key/content replays, different content conflicts. Protected disk storage, 25 MiB/file, 200 KiB UTF-8 text, 250 MiB owner quota, TXT/MD/WAV/MP4/WebM; URL imports explicitly unsupported. Browser may defer_processing=1 then POST /api/teaching/jobs/<id>/package {revision,upload_ids} for at most five sources.

GET /api/teaching/jobs and /<id>, /source, /file; POST /<id>/retry or /cancel {revision,...}; GET/PUT /<id>/draft; POST /<id>/review; GET /<id>/preview; POST /<id>/publish. Draft save/review/publish pin current revision and source/graph provenance. Publication requires confirm_reviewed, review_note, access and exact revision; idempotently retains content identity. New taxonomy proposals are separate; generated assessments do not certify until reviewed. Published source/file paths enforce lesson access. Generic course/lesson publish/unpublish/archive stays in authoring routes, not an invented teaching endpoint.

Job states queued/running/ready/failed/blocked/cancelled; fenced random claim, 900-second lease, max three attempts, explicit retry only, unknown outcome requires acknowledge_possible_charge. Cancellation cannot reverse a sent provider request. Retain completed transcriptions and provider/model provenance. Monetary spend approval remains an external run gate; token/file caps do not establish a monetary budget.

## Measurement/event and recovery contract

No new browser telemetry is needed to duplicate database-backed events. Existing allowed learning event names: lesson_started, lesson_completed, practice_saved, practice_submitted, help_requested, onboarding_completed, course_started, meaningful_return. Deduplication/completion history must stay server-owned. Do not send source, answers, learner drafts or identities to public analytics.

GET /api/admin/measurement/skills is admin-only, UTC start inclusive/end exclusive, 1–366 days, default 30 dates. Cohorts are created_in_window_current_outcome, not historical as-of-end reconstruction. Zero denominator -> null rate. Placement is original-plan observations or compatible evidence/eight-attempt cap; empty plan unavailable. Challenges split certification/practice; understanding/application acquisition deduplicated by objective revision. Cross-branch counts intentional activity, not interests; lesson-event mapping explicitly current_release_projection. Processing readiness denominator attempted jobs; claims/retries are not invoices. Publication denominator distinct first-draft job families, numerator published families. Baseline weekly learning return remains separate from competence/membership.
