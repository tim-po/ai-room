## Browser contract

All `/api/teaching/jobs` editing/review routes require the upload owner editor or administrator and existing session/CSRF protection. No answer keys are in learner preview, public capabilities, or job DTO. Existing single-file upload contract remains supported.

1. Upload every file with `POST /api/teaching/uploads`, multipart `file`, `defer_processing=1`, unique `Idempotency-Key` and `X-CSRF-Token`. This deliberately holds the source in `cancelled / awaiting_package` until assembled, avoiding a worker race. TXT/MD UTF-8 (200 KiB each), WAV/MP4/WebM (25 MiB each); 250 MiB owner quota. No URL fetching, archives or PDFs. Media signatures are validated; successful decoding is established by transcription, not by upload.
2. `POST /api/teaching/jobs/{first_upload_id}/package` with `{revision,upload_ids:[first,...]}`. At most five owner-matched, unprocessed sources. Other source jobs become `cancelled / included_in_package` and cannot be retried individually. The primary job becomes queued. `source_ids` and `draft_revision` are present in job DTOs.
3. An operator/scheduler runs `flask --app club process-teaching-once`. Jobs survive restart. Claims last 900 seconds; one claim processes at most five transcriptions and one generation call, each with a 90-second network timeout. No automatic provider retries. Explicit job retry/cancel retain work. Unknown network outcomes require acknowledgement of possible duplicate charge. Completed transcriptions persist and are reused after a generation failure. Cancellation fences stale workers from saving drafts; a request already in flight can still incur cost.
4. `GET /api/teaching/jobs/{id}/draft` returns `{job_id,revision,draft,sources,release_id,provider,model,publication}`. Source snapshots pin source ID/edition/hash and paragraphs; media adds transcript edition/hash/duration/start/end. Snapshot content is plain text, not HTML. Render with escaping. The provider-neutral schema is `DRAFT_CONTRACT` in `club/teaching_drafts.py`.
5. `PUT .../draft` with `{revision,draft}` appends a new immutable edition. Stale edits return 409. The server validates objective editions, source anchors, question coverage, independent observation keys, scope and bounded content. No practical competence is awarded. Semantic support and uniqueness of answers still require human review.
6. `GET .../preview` returns learner-safe draft content/questions without answer/rationale. Access remains an explicit editorial choice. This is a JSON contract for the review UI, not a completed UI walkthrough.
7. `POST .../publish` with `{revision,confirm_reviewed:true,access:"free"|"member",review_note:"..."}` atomically creates course/module/lesson, protected file resources/video, reviewed forms and a mapping-only graph edition. Same-revision repeat returns the existing publication. New skill proposals stay proposals; graph nodes/edges are not automatically changed. Existing reviewed forms are carried into this mapping-only release with original reviewer and parent-form provenance, so unrelated challenges remain available. Existing learner attempts/evidence remain untouched.
8. `/api/teaching/published/{lesson_id}/sources/{source_id}` retrieves the pinned snapshot. `/file` streams/downloads protected bytes; the normal lesson media route supports these published videos. Course/lesson visibility and membership are enforced at every request. Later lesson edits do not rewrite snapshots. Published drafts cannot be overwritten; existing manual archive remains available. A complete per-form withdrawal/replacement and integrated publication rollback UI remains follow-up scope.

## Real provider boundary and acceptance

The adapter uses the documented OpenAI [Chat Completions](https://platform.openai.com/docs/api-reference/chat/create) JSON response mode and [file transcription](https://developers.openai.com/api/docs/guides/speech-to-text) with `whisper-1` verbose timestamped output. Generation model is operator-configured; no model or credential is guessed. Fixed HTTPS API origin, redirects refused, no tools, no source URL requests, bounded request/response sizes, sanitized status codes only. Sources are separated from system instructions as untrusted data. Prompt instructions are defense in depth: generated drafts cannot change access or publish, and keys/files are never in generation context.

Enable only approved credentials via environment variable names `CLUB_AI_APPROVED=1`, `CLUB_AI_API_KEY`, `CLUB_AI_MODEL`. Capabilities report readiness and missing variable names, never values. No other credential store is inspected. Output cap: 6,000 completion tokens; analysis source cap: 80 KB serialized; response cap: 1 MiB. At most three explicit attempts per job. Returned transcription duration must be <=30 minutes; this is a validation bound after provider processing, not a pre-charge duration estimate. Set provider account spend limits independently. There is no dedicated permanent queue daemon in this increment; arrange a bounded operator/scheduler invocation.

Tests inject `TEACHING_PROVIDER_FACTORY` only with `TESTING=True`; production refuses alternate test adapters. Mock results do not establish provider acceptance. The approved provider configuration decision remains pending. Required real smoke: approved synthetic spoken video plus source notes, real transcription and generation, item-level editorial disposition against learning architect fixtures, UI correction/preview/publication, protected learner playback/challenge and provenance evidence. No live run or deployment is claimed by this increment.

Remaining work includes independent semantic review using `learning-architect-turn008/source-review-fixtures.json`, retained invalid provider output for editorial troubleshooting, separate graph-proposal review/rollback, optional adaptive placement and equivalent retakes, practical rubric decisions/evidence, full UI integration and independent acceptance. Invalid outputs currently fail safely with `invalid_generated_draft_or_source` and retain original uploads/transcripts; they do not become editable drafts.

## Editorial decisions (increment 008)

`POST /api/teaching/jobs/{id}/review` takes `{revision, action}` under the same owner/editor, CSRF and immutable-edition rules as PUT. One action per saved edition:

- `{kind:"remap_outcome",objective_id:"old.ability",target_id:"existing.ability"}` updates the objective edition from the pinned graph. It removes the old objective's assessments and reuse proposal: old questions are never silently certified against the new skill. Correct the explanation/source and author or review replacement questions using full PUT before publishing a challenge.
- `{kind:"reject_outcome",objective_id:"ability"}` removes the mapping and its assessments/proposal. Rejecting the last mapping is allowed; the teaching material is explicitly unmapped.
- `{kind:"remove_question",objective_id:"ability",item_id:"question"}` removes that question. If the remaining form lacks sufficient independent coverage, the whole form is removed from this edition. The prior edition retains all removed work. A sufficient remaining form stays available for editorial review.
- `{kind:"remove_assessment",objective_id:"ability"}` removes the entire form.

Response is the normal draft DTO plus `review_changes.removed_assessments`. Draft and preview DTOs now include `coverage: {mapped,challenge_available,assessed_objectives,unassessed_objectives}`. These describe this draft's proposed assessments, not other published challenges on the same node; they do not claim semantic quality or learner competence. UI must show removed forms and unassessed/unmapped state before publication. Publishing unassessed material creates no new challenge or evidence. Unrelated preexisting reviewed forms remain preserved.

Source-anchor correction uses existing full `PUT .../draft`: select source_id/edition/sha256/paragraph from returned pinned `sources` for any outcome, practice or question reference. Every anchor is validated and canonicalized, including media times. Unknown anchors fail atomically; preview/save/reopen/publication preserve selection. A full PUT with inconsistent mapping/question targets fails instead of silently changing assessment meaning. Unknown review actions return 400; stale or published editions return 409; other editors cannot access owner drafts. No migration is needed.
