# Derived skill and teaching measurement

`GET /api/admin/measurement/skills?start=2026-10-01&end=2026-11-01`

Administrator only; anonymous 401, learner/editor 403. UTC ISO dates, start inclusive and end exclusive, 1–366 days; default last 30 calendar dates including today. Invalid dates/windows return 400. Before `init-skills` and `init-teaching`, returns explicit 503 initialization dependency rather than invented zero metrics. No schema migration or new event emission is needed. Existing baseline `/admin/measurement` is unchanged. Worker may link or render this separate API from that page.

The response is aggregate only: counts, rates, date/version metadata and the active lesson-mapping release. It contains no learner IDs, responses, work, source text, provider errors, private filenames or review comments. Learner metrics exclude current editor/admin accounts; processing/publication count editorial activity. Role is current role because historical role snapshots are not stored.

## Definitions

All cohort outcomes are **current when queried**, not reconstructed at the window end. `observed_at` and `semantics=created_in_window_current_outcome` make this explicit. A January-created attempt finished in February is completed in a January cohort queried in March. Zero denominators return `rate: null`, never zero percent.

- `placement`: sessions created in the window, partitioned into completed, stopped, unfinished and unavailable. Stopped is persisted skipped state. Completed means all objectives in the original available-form plan have recorded observations or revision-compatible understanding evidence, or the diagnostic reached its eight-observation cap. It means the check is finished, not that the learner passed. Empty assessment plans are unavailable, not successful completion. Withdrawn/inaccessible forms do not silently turn unfinished sessions into successes. This intentionally stricter measurement can differ from the learner UI's dynamic “no next form” state. Counts include every started session; completion denominator includes stopped/unavailable sessions. Later compatible evidence can resolve an earlier plan.
- `challenges`: attempts created in the window, separately certification and practice. Each has started, completed, unfinished and passed counts. Persisted result identity deduplicates retries. Passing is never substituted for credit; practice retakes can pass without credit.
- `evidence`: credits earned in the window, separately understanding and application. Uniqueness is learner/objective/revision, matching the immutable primary keys. Compatible graph editions do not mint additional credit. Historical credit remains counted after later objective retirement; this is acquisition history, not current mastery. Application is human-reviewed evidence, not a saved practice draft.
- `cross_branch`: distinct learners with intentional activity across at least two major branches / learners with any qualifying activity. Qualifying activity is a created challenge, created practical submission (including drafts), or persisted lesson_started/lesson_completed/practice_saved/practice_submitted event in the window. Foundation or unmapped activity belongs in the denominator even with no major branch. Mere exploration/preferences never enters this rate. `exploration_learners` is a separate distinct count based on latest exploration timestamps. Challenge/practical attribution follows the immutable original form's graph; lesson events lack historical release IDs and therefore explicitly use `current_release_projection`. `activities_without_major_branch` counts lesson events without a mapped major branch, including foundations. Legacy event deduplication means this is **recorded intentional activity**, not every repeat lesson visit. It is not a retention measure. A genuinely multi-mapped lesson can contribute to multiple branches.
- `processing`: distinct jobs created in the window, all current states, attempted_jobs (attempt > 0), retries (`sum(max(attempt-1,0))`), jobs_retried and readiness = currently ready attempted jobs / attempted jobs. Queued or cancelled before first claim remains visible in states but outside the readiness denominator. Attempt counters count claimed processing runs, not provider invoices; do not infer costs or live-provider success from this measure.
- `publication`: distinct published job/draft families / distinct review-ready job/draft families whose first immutable draft was created in the window. Multiple edits and idempotent publication do not inflate either count. A later publication counts as a current outcome of its original review-ready cohort. Publishing is not proof of provider semantics or learning quality.

No subscription renewal or invented improvement is reported. Baseline first-practical-result continues to measure the original lesson practice flow; this endpoint does not relabel it as revised application verification.

## Validation

`PYTHONPATH=. /home/claude/ai-room/.venv/bin/pytest -q tests/test_skill_measurement.py tests/test_measurement.py`

Tests use isolated SQLite databases, real authenticated placement/challenge/practical-review endpoints, and controlled job/draft fixtures. They verify authorization, initialization errors, windows, null denominators, stopped/unfinished placement, practice versus certification, replay-safe understanding/application credit, intentional multibranch activity versus exploration, distinct publication families, retry/state denominators and aggregate privacy. Controlled processing rows test query arithmetic only; they are not provider-backed AI evidence.
