## A — Мастерская / editorial workshop

Promise: an achievable piece of work, not a collection of status counters. Warm paper, graphite text, vermilion actions and forest-green foundation. Large left-aligned Cyrillic headline balanced by an original isometric notebook illustration. Quiet rules, spacious margins, typographic side notes and material examples form a coherent visual grammar through welcome, lesson and return. The map is a working atlas on the same paper, with broad readable nodes rather than tiny icons in a huge black field.

Composition: desktop welcome is asymmetric 1:1 text/art; onboarding uses a slim step rail and a focused form; lesson uses curriculum / 680px reading column / margin note; return leads with the last artifact. At 768 the margin note follows reading content and map details sit below; at 360/390 everything flows as one column. Mobile map becomes a connected root-and-branches outline, not a shrunken desktop canvas. The actual product must preserve selected node, depth, scroll and filter when switching list/map or closing detail.

Tokens: paper #F5F2E9, surface #FFFDF7, ink #292E28, muted #60655C, line #D4D5C8, primary #B13C25, foundation #245646. Reserve saturated surfaces for one next action and meaningful map orientation. Borders are structural, not decorative cards around every paragraph. Small radii 8/12/14px; paper examples 4px. No large blurry shadows.

Font: Golos Text locally loaded, normal copy 16px / 1.55, lesson prose 17–18px / 1.65 target; headings 70/44/32/25 desktop and 42/34/24 mobile, weight 520–600. Eyebrow 11px with 0.12em spacing is secondary metadata only; essential node titles minimum 14px. Avoid all-caps sentences. Keep long lesson text around 60–75 Cyrillic characters per line. Spacing scale 4/8/12/16/24/32/48/64; mobile margins 20px, tablet 5vw, desktop capped at 1440px.

Headline 68 desktop / 42 mobile; lesson 40 / 34. Radii 24/28px, branch capsules 40px. Artwork has no animation by default. Same semantic states and accessible controls as A.

Self-critique: B is more visually exploratory but darker reading surfaces and extra container padding can make mobile practice feel heavier. A gives lessons and saved work a clearer editorial identity and is less similar to the rejected dark-dashboard baseline. Both prototypes deliberately use only a small graph to assess composition; neither proves recursive navigation or real account continuity. Branch icons remain modest in scale; final production needs a richer family of subject illustrations in discovery and course openings, not one repeated decorative motif everywhere.

## Branch, interaction and illustration contract

One shared root: Базовые знания об AI. Five siblings: Кодинг с AI, AI-команды, Создание контента, Автоматизация, Агенты. Distinct geometric subjects: code window, collaborating circles, editorial document, branching workflow, compass; foundation uses a simple structured volume. Icons are inline SVG, 64-unit canvas, 1.8-unit strokes with consistent joins, aria-hidden beside visible text. Never use emoji or repeated placeholder stars as branch artwork. Original code-native artwork is included; no stock/AI image rights dependency.

Production graph: a contains edge is a solid quiet connector; readiness is a labelled advisory relation, never a padlock on a sibling; cross-reference is dotted and explicitly labelled. Show at most parent + selected sibling cluster + one level of children at once. Breadcrumb and back-to-parent preserve spatial context. Coding's design/mobile/review/web/testing/existing-code are siblings, never a mandatory sequence. Color is redundant with label and icon. Unknown is open circle + «Ещё не проверено»; saved work uses document + «Черновик»; reviewed evidence uses explicit status and source. Completion, practice submission, membership and proficiency must never share one green tick meaning.

Interaction sizes: minimum 44px targets; explicit map/list and recenter; real HTML buttons for nodes, semantic form labels, visible 3px focus with 5px offset. Keyboard order follows root then siblings, never canvas coordinates. Use roving focus only with documented arrow-key behavior and an equivalent list. Mobile selected detail must open adjacent to selection or as a labelled sheet with focus return; prototype detail currently follows the full tree and this remains a production design gate. No drag-only controls. Search needs a labelled zero-results state and reset; prototype shows filtering only and is not the final error/empty contract.

Motion: optional 120–180ms opacity/position transitions, never required to orient. Respect reduced motion; no ambient star animation or punitive streak effect. At 200% zoom use the narrow composition without clipping actions. Header in onboarding removes competing global navigation; keep a clear skip, back and progress label. Maintain server-side step and field persistence with pending/success/error status in the implemented product; the prototype does not simulate server persistence.

## Complete-product composition contract for frontend

- Welcome/access: one clear promise and primary start; login/recovery in the same shell. Fresh sign-in automatically enters onboarding; direct lesson destination survives skip/finish. Existing-account edit must preserve learning.
- Discovery: editorial title, compact search, collapsible filters and spacious outcome-led rows with small subject artwork. Show real access/time/progress. Do not repeat huge dashboard cards. Empty filtered state includes reset.
- Course: outcome and named start above a long ordered expandable curriculum; retain the real 37-lesson capability. Restrict hero metadata to learner decisions. Programme must work on mobile without pinning three sidebars.
- Video/text lesson: use A's readable column, lesson goal, concise example and adjacent task. Real player with real fallback/transcript; never fake play artwork. Saved draft, submitted work and reviewed result are separate. Materials should not bury practice.
- Challenge/results: one question region and stable response controls; source explanation immediately follows submission. Show coverage and unknown areas honestly; partial result names the next useful lesson. Unavailable assessment offers a learning route, not a misleading completion state.
- Profile/return: latest work and named continuation first. Evidence and branch strengths below progressive disclosure. Unknown areas must not dominate the first screen. Long absence has the same calm resumption without reset or penalty.
- Favorites/help/preferences/access: reuse paper, field, disclosure and action components. Recovery actions must be live; no “coming soon” button disguised as an action. Access/readiness visibly separate.
- Loading/error/offline: reserve dimensions, plain Russian status near the action, retain typed draft, retry with same payload, sign-in return target when expired. Forbidden/unpublished states offer permitted alternatives; unavailable video leaves text/materials reachable. All of these are unverified until production routes are exercised.

Acceptance tasks trace research D01/D02/D04/D09: (1) two interests and step survive real refresh/login; (2) first lesson supplies an understandable attempt and honest example-based feedback; (3) saved work reopens from first mobile profile viewport; (4) optional exploration does not reset learning. Screenshot aesthetics cannot substitute for these backend-connected tasks.
