Loop requirements

Mission

Manufacture the product feel: deliver a beautiful, comprehensive Russian-first educational platform with a distinctive identity, effortless onboarding and useful reasons to return. Owner says current UI looks really bad and onboarding is not visible. Treat that as a product failure requiring substantial redesign. Deliver working connected learner UI, not research-only reports, static mockups, a tree-only reskin or another dashboard of generic cards.

Research

Before design selection, browse and inspect at least five relevant education products spanning guided practice, technical skill development and course learning (examples to investigate, not endorsed claims: Duolingo, Brilliant, Khan Academy, Codecademy, Coursera). Document source URLs, access dates, screenshots where accessible, onboarding/first-value/lesson/feedback/return patterns and limitations. Use primary product documentation and primary learning-science studies for factual claims. Separate observed UI patterns, marketing claims, causal evidence and hypotheses; do not invent conversion or retention data. Use available anonymized platform analytics only with cohort/window/fixture caveats. Turn each selected insight into a concrete design decision and acceptance task; research must change the product.

Identity

Art director must produce two genuinely distinct visual directions rendered as working HTML views with realistic Russian content, each including welcome/onboarding, skill map and lesson at desktop/mobile. Independently critique them, choose and record one before broad rollout. Define loaded Cyrillic fonts, typography scale, spacing, composition, color, illustration/art direction, icon system, branch/node language, focus, motion and responsive behavior. Use first-iteration strengths and Orbit/Campus as references, not copy-paste. Intentional crafted surfaces, clear hierarchy and purposeful art must replace generic empty panels, dense metadata and repeated placeholder glyphs. A coherent learner product takes priority over map decoration.

Learner scope

- Welcome and sign-in/access states with a clear product promise and obvious first action; new signed-in learner actually encounters onboarding automatically. Existing learner has a visible restart/edit entry. Demonstrate with genuinely fresh accounts, not only direct /onboarding links.

- Short multi-step Russian onboarding: welcome/value, optional multiple interests, experience and time, optional diagnostic, personalized but nonexclusive start and first achievable activity. Skip, back, resume after refresh/logout, edit preferences and returning states must work and persist server-side. No mandatory class, single route or questionnaire disguised as a settings page.

- Central inviting skill map: one Basic AI Knowledge root, Coding with AI, AI Teams, Content Creation, Automation, Agents; recursive sibling subbranches, progressive disclosure, legible branch art and spatial relationships, search/recenter, keyboard/touch controls, synchronized list, concise node detail and mobile context preservation. Many simultaneous interests/progress; readiness distinct from membership.

- Complete supporting surfaces: discover/search/filter, realistic long course curriculum, readable video/text lesson with materials/practice and resume, challenge entry/questions/results/source explanations, character/profile with evidence and unknown states, saved work/favorites, help, preferences and account/access recovery. Retain existing baseline functions; tree must connect to actual learning.

- Design the complete first useful result: discover ability -> learn/practice -> meaningful feedback -> save progress -> clear next action. Design interrupted session, return next day, completed unit, weak/partial result, multi-branch exploration and return after long absence.

- Retention through useful progress, achievable practice, timely feedback, continuity and optional flexible goals. Use evidence-backed retrieval/spaced-review patterns where existing reviewed content supports them. No punitive streaks, fabricated urgency, addictive friction, leaderboards or forced specialization. New grading algorithms belong to backend loop; UI cannot manufacture competence.

- Comprehensive loading/empty/offline/error/forbidden/expired/unpublished/media failure and assessment-unknown states. Useful concise copy and real recovery actions. No dead-end demo controls.

Onboarding acceptance

Fresh synthetic novice completes or skips onboarding, chooses at least two interests, reaches a permitted first activity without developer instructions, saves first practical result, signs out/in and sees the correct continuation. Experienced learner can skip and challenge a topic; interrupted onboarding resumes; returning learner can edit interests without resetting learning. Record actual headless Chromium journeys, screen sequence and task observations. Agent walkthroughs must be labelled expert/simulated evaluations, never real human usability studies.

Visual gate

Use actual headless Chromium (Playwright or equivalent) against running app at 360,390,768,1440 widths. Capture durable baseline and final full-page AND task/viewport screenshots of welcome/onboarding steps, map overview/selection/deep branch/list/mobile detail, discovery/course, video/text lesson/practice, challenge/feedback, profile empty/uneven strengths, return and error states. Reviewers OPEN and visually inspect images and interact with app. Compare to selected benchmark for identity, composition, hierarchy, typography, imagery, density, orientation and perceived finish. Record concrete failures with screenshot paths and expected corrections. Pixel diffs/contrast/no-overflow/HTTP checks are supplemental. Test keyboard focus, touch alternatives, reduced motion, 200% zoom and long Cyrillic text. All critical journeys and surfaces must pass explicit design and task acceptance; a numeric average cannot hide a failing core screen.

Measurement

Define and implement minimal privacy-preserving events for onboarding exposure/step/skip/completion, first meaningful activity/result, lesson resume, feedback and meaningful return, coordinating backend ownership. Report activation, funnel drop-off, time-to-first-result and cohort D1/D7 meaningful learning return with explicit denominators and windows. Synthetic smoke data validates instrumentation only. Propose measurable retention hypotheses and future experiments, do not claim achieved uplift before real observation.

Deliver implemented learner app, research-to-decision register, selected visual system, real onboarding, connected journeys, labeled credible teaching content, durable before/after screenshot gallery, independent visual and functional verdicts, event definitions, exact commit/content ledger, staging URL and rollback handoff. AI provider issues must not block unrelated learner visual work; explicitly carry unmet engine dependencies to backend loop. No overall platform-complete claim while those remain.
